# PS5 Input Bridge

Windows x64 局域网手柄桥接原型。**手柄接 PC，画面看 PS5 / PS5 Pro 直连电视。**

原生 libchiaki 处理配对和 Remote Play 输入，独立线程直接采集 XInput 手柄；WPF 界面只负责账户和连接。普通音视频处理关闭，没有视频解码、显示、音频播放或麦克风采集。它不是 Sony 官方客户端。

## 启动与配对

1. 在 PC 启动 `dist/PS5InputBridge/Ps5InputBridge.exe`。发行目录包含 .NET 运行时，不需要另外安装；请保持整个目录完整，不要只复制 exe。
2. PC 与 PS5 接同一有线局域网，PS5 保持开机。手柄接 PC。两种接法：**Xbox / XInput / PC 模式**（四个 XInput 槽位），或 **DS / PS4 / PS5 模式**（DualShock 4、DualSense 以及用这两种报告格式的第三方手柄，程序以 HID 直读；手柄列表中显示为“HID 直读”）。HID 直读按报告到达处理，并支持触摸板滑动；不支持其他 DirectInput 手柄。没有手柄时也可以连接，随后插入手柄。
3. 在 PS5 登录要控制的账户，打开 **设置 → 系统 → 远程游玩 → 启用远程游玩**。在网络设置查看主机局域网 IP。
4. 展开 **导入、导出与添加账户**，点击 **添加并配对**，填写账户显示名称、主机 IP、该 PSN 账户的 **Account-ID（Base64）**。
5. 在 PS5 的远程游玩设置选择 **关联设备**，将新显示的 **8 位配对码**填入程序并配对。每个 PSN 账户完成一次；不需要每次切换重复配对。

Account-ID 是 8 字节账户编号的 Base64 编码，**不是 PSN 昵称、邮箱或密码**。如果已有 Chiaki 配对资料，可以从其注册界面查到。没有时，可按 [chiaki-ng 官方注册指南](https://streetpea.github.io/chiaki-ng/setup/configuration/#registering-your-playstation) 的 Account-ID 方法获取，或使用固定版本的[上游账户编号脚本](https://github.com/chiaki-ng/chiaki-ng/blob/0c4a45df0cae2af2ba2daef84e881850b07038a3/scripts/psn-account-id.py)。在浏览器的 Sony 登录页面操作；本程序的配对表单不要求 PSN 密码。不要将含授权码的跳转网址或访问令牌发送给他人。

**换一台电脑**：在原来那台点 **导出账户文件**，设置一个至少 8 位的密码，得到一个 `.bridge` 文件；把整个 `PS5InputBridge` 目录和这个文件拷到新电脑，打开程序点 **导入账户文件** 并输入同一密码即可，不需要重新配对。文件用 PBKDF2（30 万次迭代）派生密钥加 AES-GCM 加密，但**它等同于你的配对凭据，任何拿到文件和密码的人都能连上你的主机**，用完请删除或妥善保管。新电脑仍需与 PS5 在同一局域网，若主机 IP 变了，选择账户后点 **编辑名称 / 地址** 修正 IP，原配对资料可继续使用。

**已在 Helios 配对过**：点 **从 Helios 导入**，程序读取同一 Windows 用户下 Helios 的 PS Remote Play 账户（`%LOCALAPPDATA%\HeliosProject\Helios\remote_play\playstation\credentials.dat`），直接沿用其配对凭据，不需要重新配对。只导入 PS5 账户；相同配对凭据已存在的会跳过。Helios 不保存 Base64 Account-ID，导入的账户不带 Account-ID：局域网连接只用注册密钥和 morning 密钥认证，不受影响；以后若要重新配对，再按下文获取 Account-ID。凭据只在本机内存中解密并立即重新加密保存，不会显示或上传。

**已在 Chiaki / Chiaki-ng 配对过**：点 **从 Chiaki 导入**，程序会读取同一 Windows 用户的桌面版 Chiaki / Chiaki-ng 本机配置（包括具名配置），列出可导入的 PS5 账户。也可以点 **选择配置文件…**，选择从 Chiaki-ng 设置中导出的 `.ini` 文件，或桌面版 Chiaki 的 Qt `.conf` 配置文件。两个版本使用相同的核心配对字段，程序会按实际配置读取，无需手动选择版本；不支持 Android、Switch 等版本的其他导出格式。

导入预览中，每个账户分别填写 **账户名称（仅用于区分）** 和 **PS5 局域网 IP 或主机名**。改名称不会改变 IP；请不要把昵称填进地址栏。Chiaki 的配对记录本身通常没有 IP；程序会按主机 MAC 关联手动保存的地址，没有可用地址时需补填，IP 已变化时也可以直接修改。点击 **确认导入** 才会使用现有加密账户存储保存，点击取消不保存。不需要重新配对，也不需要 Account-ID；只导入 PS5，重复凭据（包括已从 Helios 导入的）会跳过，数据不完整的记录会提示跳过。不导入 PSN 令牌、密码或已保存的主机登录 PIN。

账户配对成功才会保存。文件位于 `%LOCALAPPDATA%\PS5InputBridge\accounts.dat`，使用当前 Windows 用户的 DPAPI 加密；复制到另一 Windows 用户通常不能解密。程序不保存 PSN 密码或主机 4 位登录密码。

## 使用与切换账户

- 选择已保存账户和手柄后点 **连接**；只有主机报告完成连接才显示“已连接”。
- 连接过程中选择另一个账户，会先释放按键并结束旧会话，再使用新账户凭据连接。一次控制一个账户；实际连接速度由 PS5 会话握手决定。
- **Ctrl + 1…9** 按列表顺序选择并连接账户；**Ctrl + D** 断开。快捷键在程序窗口有焦点时生效。
- 账户有 PS5 **4 位主机登录密码**时，连接会弹窗请求，不会保存。它不同于 PSN 密码和 8 位设备配对码。
- HID 直读手柄的全部按键（含 PS、Create/Share、触摸板点击和双指触摸滑动）直接转发，不需要映射；Back 键映射选项只对 XInput 手柄生效。蓝牙连接的 DS4 / DualSense 也能直读（程序会切换到完整报告），但蓝牙本身的延迟和抖动高于有线。
- PS 键、触摸板点击可通过界面按钮触发。XInput 的 A/B/X/Y 分别映射到叉/圈/方块/三角，Start 映射 Options，手柄 Home / Xbox 键映射 PS 键（通过 XInput 扩展接口读取；Windows Xbox Game Bar 若占用该键，请在“设置 → 游戏 → Xbox Game Bar”关闭“使用控制器上的此按钮打开”）。Back / View 键默认映射**触摸板点击**（PS5 游戏里的地图、记分板，如 Apex 的地图）；需要截图、录屏时可在界面改为“分享 / Create”，连接中切换立即生效。
- 断开和关窗释放输入并结束会话，不要求主机待机。网络已经中断时无法保证释放报文送达主机。

账户区提供 **编辑名称 / 地址** 与 **删除账户**。只改名称不会断开；修改当前账户地址会先断开，保存后点击连接即可，无需重新配对。删除会确认，并且只删除本程序的记录，不改 Chiaki 或 PS5；删除当前账户先停止会话，不自动连接剩余账户。保存失败保留原列表。

程序记住上次选择的账户、手柄、采样档和 Back 映射，保存在 `%LOCALAPPDATA%\PS5InputBridge\preferences.json`；启动仅恢复选择，不自动连接。每个 Windows 用户限制一个运行实例，避免两个窗口覆盖同一份账户。

账户修复与使用体验改进的测试证据见 [验证记录](docs/validation/2026-10-23-account-usability.md)。给朋友使用可发送 `dist/PS5InputBridge-win-x64.zip`，其中包含完整程序及对应源码包，完整解压后运行 `PS5InputBridge` 文件夹中的程序。

连接后切换手柄或 XInput 采样档直接生效，无需重新建立 PS5 会话。HID 模式下采样档不可操作，但会保留 XInput 的档位。HID 根据设备接口路径绑定，拔掉另一只手柄不会因为序号重排而选错；原设备离线时等待它恢复，换 USB 口或切换 USB / 蓝牙可能需要重新选择一次。打不开或读取失败会显示针对性的提示。

**导出诊断…** 保存最近最多 256 条状态变化、随机会话标识、输入计数、设置和延迟统计。1.0.1 起另保留最多 256 条每秒采样的 XInput 读取记录，包含原始摇杆/按键值、包序号、读取耗时、距上次读取/包变化的时间、错误码和读取卡住次数；即使状态已恢复，错误计数仍会保留。不含账户名称、IP、设备路径、配对密钥、PIN 或令牌。账户文件导入/导出的密码计算在后台执行；账户包上限 1 MB / 64 个账户，兼容本程序已有的 30 万次迭代格式。

XInput 读取调用超过 250 ms 未返回时，独立监控会在随后一次检查中释放摇杆和按键，报告读取超时；读取恢复后继续转发。正常长按、包序号不变不会触发此保护。它不能重启卡住的 USB 驱动，也无法识别驱动不断成功返回旧值的情况。如果仍出现转圈或输入冻结，请尽量在插拔前导出诊断，以保留故障现场；也可切到 500 μs 档对照。详见 [本次排查和验证](docs/validation/2026-10-25-input-recovery.md)。

## 延迟目标与统计

**HID 直读手柄没有采样间隔**：输入线程等待报告完成事件，报告到达即解析、加密并发出；采样间隔选项对它无效。实际报告率由手柄、固件、连接方式和当前模式决定，Xbox 模式的 8K 标称不能直接套用到 DS/HID 模式。XInput 手柄默认 **500 μs（0.5 ms）**采集间隔；**100 μs 极限档**在连接期间持续忙等计时，空闲不降速，约占用一个 CPU 核心；输入线程申请 MMCSS 调度并在极限档设置低于普通的线程优先级，实际间隔仍受系统调度影响；**1000 μs** 档降低 CPU 占用。Windows 定时器只能按约 0.5 ms 的节拍唤醒，程序已按实测补偿，500 μs 档实际约 0.5 ms（修正前实际约 1 ms）。这是 PC 读取手柄的间隔，不代表手柄 USB 回报率或端到端延迟。系统负载、调度、XInput 驱动和手柄本身仍会影响实际间隔。

输入线程检测到变化后**在同一线程内直接加密并发出 UDP 包**，不再排队等待 libchiaki 的反馈线程；每次采样只要状态变化（按键、扳机、摇杆）就立即发送，不做合并。按键打包沿用 chiaki-ng 官方规则（#823/#838/#840）：**每个按键/扳机变化单独一个包**，包头写明包内事件数，同一次采样里同时变化的几个键（例如松开 L2 的同时 R2 在变）会依次各发一个包，用于修复“松开左扳机却一直开镜”的漏事件问题。每个包附带最近 8 个事件；最后一个包会在约 20 / 50 / 100 / 200 ms 后重发（每次新序号），弥补丢包。摇杆状态变化立即发送，另有约 200 ms 保活；摇杆停止的包若丢失，最迟由保活恢复。本地发送失败会返回给调用方并由上述重发补上。上述时间是调度目标，恢复效果受调度、网络和主机行为影响。摇杆没有附加曲线、死区或人为平滑；输入线程注册 MMCSS “Pro Audio” 调度。

当前整合版 **1.1.1** 基于 chiaki-ng main `c8bea2642d`，同时保留 1.1.0 的上游 #823/#838/#840 修复和此前的延迟优化。输入线程仍同步首发，停止时等待 30 ms 以发送第一次松开补发。摇杆丢包由约 200 ms 保活恢复；仍需在 PS5 上复测。详见 [重建说明](docs/plans/2026-10-29-rebuild-on-chiaki-ng-main.md) 和 [整合验证](docs/validation/2026-10-29-integrated-release.md)。

保留小包缓冲、加密初始化、HID 读取与统计快照优化。反馈线程唤醒和补发时序改为新版上游行为；此前 [8K 优化验证](docs/validation/2026-10-26-8k-input-optimization.md) 的数值仅描述旧发送器。

保留 1.0.5-latency.1 的统计优化：HID 和 XInput 默认均关闭逐报告详细延迟计算和统计窗口，界面延迟显示“—”，保留提交次数、错误计数和输入故障保护。`PS5BRIDGE_XINPUT_TIMING=1` 单独恢复 XInput 详细计时；原 `PS5BRIDGE_TRACE=1` 仍可恢复两种模式的详细计时和按键边沿记录。XInput 的采样、读取超时和故障检测仍保留必要时间戳。HID 正常报告只进入一次共享提交锁；已同步完成的读取省去事件等待。输入顺序、摇杆数值和按键边沿不做合并。

详细时序窗口约每 100ms 非阻塞发布到独立统计快照；界面读取不再锁住输入侧的整个窗口，快照忙时输入线程跳过统计更新，继续发送。手柄切换和重新连接会清空旧设备时序；切换时保留会话失败计数。

`PS5BRIDGE_DIAGNOSTICS=1` 可独立开启有界的锁等待/发送调用诊断，默认关闭；断开后导出到 `%LOCALAPPDATA%\PS5InputBridge\diagnostics`，只包含阶段、时间及计数，无按键值或凭据。这些记录不含 USB 到达、网卡实际出线或 PS5 接收时间。发行包内含普通、计时和诊断启动器，见 [使用说明](docs/validation/2026-10-29-latency-test-guide.md)。

1.0.3 的受控 HID 读取与真实加密 UDP 环回对照中，1K 连续变化的生成至本地提交均值为 30.098→29.724 μs，属于小幅改善；没有验证真实 USB 或 PS5 端到端延迟。测试方法、压力场景和边界见 [HID 优化验证](docs/validation/2026-10-26-hid-latency.md)。

现场排查漏键：启动前设置环境变量 `PS5BRIDGE_TRACE=1`，可恢复 HID 详细计时；断开后会在 `%LOCALAPPDATA%\PS5InputBridge\trace-*.csv` 写出每次按键/扳机边沿的时间与提交结果。诊断会增加计时和统计开销，日常使用无需开启。

启用计时时，界面的“PC 采集 → 提交”测 **XInput 取到状态（或应用取出 HID 报告）后，到原生提交函数成功返回**的耗时，正常变化提交包含加密和 UDP 发送调用；后台已恢复的待发送状态可能无需再次发送。仅统计连接完成后的成功提交，不把连接期间的输入缓存算作发送。它不包含手柄/USB 延迟、驱动排队、等待采样或线程唤醒、网络、PS5 处理和电视显示。报告次数是提交次数，不是 UDP 包数（补发包不计）。

新增近期提交 P95/P99、实际采集间隔的平均值/P95/P99，用最近最多 1024 个样本观察抖动；采集间隔仅统计同一手柄在线且连接完成后的连续采样，HID 下反映报告读取间隔，100 μs 档空闲时也保持高速采样。“提交失败”是本次连接的前台提交失败次数，包含等待重试期间的重复调用，不是 UDP 丢包数，也不包含后台重发失败次数。详细测试和边界见 [本轮验证记录](docs/validation/2026-10-23-latency-reliability.md)。

禁用音视频使用上游选项；主机实际是否完全停发媒体尚未实机抓包验证。**本原型尚未证明延迟不高于 Brook Wingman FGC 2。** 对照方法及证据见 [研究记录](docs/research/2026-10-09-ps5-pro-input-bridge.md)。

## 开发、构建与本地测试

需要 .NET 9 SDK、Python 3.11+、PowerShell 7。首次原生构建需要联网下载项目内工具链和固定依赖，之后可复用缓存；无需安装系统 C/C++ 编译器。

```powershell
pwsh -NoProfile -File tools/build-native.ps1
dotnet test tests/Ps5Bridge.Tests/Ps5Bridge.Tests.csproj -c Release
dotnet run --project tests/Ps5Bridge.UiChecks/UiChecks.csproj -c Release
pwsh -NoProfile -File tools/publish.ps1 -SkipNativeBuild
```

账户切换/取消/存储测试使用可控后端；DPAPI 测试使用真实 Windows 加密接口；原生 ABI 测试加载实际 DLL，并测试无有效主机、真实注册取消、循环创建销毁及本地 TCP 模拟主机不回应时的停止路径。UI 已做本地启动、布局和关闭验证。

`Ps5Bridge.UiChecks` 使用合成账户离线检查五账户分别命名、编辑/删除/保存失败、连接中删除、启动偏好、单实例互斥、导入确认/取消以及普通/最小窗口宽度下的布局，截图写入 `artifacts/chiaki-ui-validation/`；不读取真实账户或 Chiaki 配置，不连接 PS5。

没有连接用户的真实 PS5 Pro，因此 **实机配对、账户切换、输入正确性、漏键/卡键、完全停传媒体及实际端到端延迟**仍需现场测试。自动化本地测试不能代替这些验证。

## 源码与许可

基于 chiaki-ng main 固定提交 `c8bea2642d0e95402f373af55584a3b98cd89417`。上游发送器、错误返回、可选诊断与小包缓冲修改记录在 `native/patches/chiaki-edits.json`，保留的加密优化记录在 `native/patches/chiaki-low-latency.json`，不再整文件替换。bootstrap 按 URL 缓存并在 pin 改变时替换旧源码，补丁基线不匹配会中止。原生 ABI 仍为 6；许可和对应源码分发要求见 `LICENSE`、`THIRD-PARTY-NOTICES.md` 和 `native/README.md`。
