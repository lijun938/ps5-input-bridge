# Windows native PS5 input bridge

## 1.1.1 statistics and diagnostic paths

Public ABI remains 6. XInput detailed timing is now opt-in with `PS5BRIDGE_XINPUT_TIMING=1` or the existing `PS5BRIDGE_TRACE=1`; HID retains trace-only detailed timing. Required poll/watchdog timestamps, raw read health and failure/release behavior remain active. Display-only read-duration conversion happens in the getter. Timing getters read a separate snapshot published about every 100 ms; the input writer uses `TryEnterCriticalSection` and skips a busy UI snapshot. Device/session changes invalidate prior timing windows; failure totals remain independent. Other small state getters still use the context lock.

`PS5BRIDGE_DIAGNOSTICS=1` enables bounded input/feedback stage recorders. They retain the last 4096 samples per stage and full-session counts/sum/max, allocate only at setup, and export after worker shutdown. `PS5BRIDGE_DIAGNOSTICS_DIR` may specify an absolute existing/creatable directory; default is `%LOCALAPPDATA%/PS5InputBridge/diagnostics`. The CSV contains no input values or credentials. Input records context-lock acquisition waits and successful connected HID report processing after retrieval; feedback records state-mutex acquisition, send calls and active retry-lock holding. Neither measures hardware report arrival, NIC wire time or console receipt. Default-off paths do not call diagnostic clocks or allocate sample buffers. This does not change input delivery, protocol bytes, retry timing or stop sequencing.

`ps5bridge.dll` exports C ABI version 6 in `include/ps5bridge.h`. The matching managed backend requires ABI 6; ship the DLL and app together. The UI owns account profiles and DPAPI storage; this DLL owns PS5 registration, a single local-network session, and an independent controller input thread. It never requests putting the console into rest mode.

Build from the repository root with:

```powershell
pwsh -NoProfile -File tools/build-native.ps1
```

The bootstrap downloads the pinned chiaki-ng main commit `c8bea2642d0e95402f373af55584a3b98cd89417` (2026-10-09, includes the feedback history fixes #823, #838 and #840), its pinned submodules, mbedTLS 2.28.0, json-c 0.17, miniupnpc 2.2.8, libevent 2.1.12, protoc 25.3, and a SHA-256 checked LLVM-MinGW 20261006 toolchain. CMake 3.31.6, Ninja 1.11.1.4 and protobuf 4.25.6 are installed in a project-local Python environment. Python 3.11+ and Internet access are needed on the first build. Downloaded sources, tools, build files and output binaries are ignored by Git; neither a system compiler nor an administrator installer is required. Release output is `native/out/ps5bridge.dll` (x64). Its dependencies are Windows system DLLs only.

Controller indices 0–3 are Windows XInput slots; indices 4 and above are HID gamepads read directly (`pb_hid_devices` lists them in device-path order; `pb_controller_mask` sets bit 4+n for each). HID pads are recognised by a Sony vendor ID, or by the DualShock 4 / DualSense report sizes (input 64, output 32/48, feature 64) for third-party pads in DS mode; the parser handles USB report 0x01 and the Bluetooth reports 0x11 (DS4) / 0x31 (DualSense), and reads the calibration feature report once so a Bluetooth pad switches to its full report. Each input report is consumed as it arrives from an overlapped `ReadFile` (8 queued buffers), so there is no sampling interval on that path; sticks map 0x80 to 0 with the full signed range, triggers are the raw bytes, two touchpad contacts are forwarded with DS4 rows rescaled to the PS5 range, and the IMU is not forwarded. Device enumeration is cached for 1 s. The XInput path uses the original signed stick range and trigger bytes, without adding a deadzone or curve. Every sample whose state changed is submitted at once (no analog coalescing). Feedback follows upstream chiaki-ng: every button/trigger/touch change is its own history packet (releases, then touch, then presses, then L2/R2), the header carries the packet's event count, each packet includes the newest event and up to 8 prior events, and the newest packet is resent at about 20/50/100/200 ms with new sequence numbers. The bridge sends these packets (and the stick state) itself on the input thread; the sender thread keeps the tail resends and the 200 ms state keepalive, and both send under the sender's lock so packets never interleave. A lost stick-stop packet is repaired by that keepalive. Local transport errors propagate through Takion, feedback sender and session; the tail resends deliver the failed packet, and an unchanged resubmission is accepted without sending again. A controller slot change submits neutral once, even when transmission fails. The input thread joins MMCSS "Pro Audio"; `PS5BRIDGE_TRACE=1` writes an edge trace CSV to `%LOCALAPPDATA%\PS5InputBridge` on stop. Input capture does not run on the UI thread, and there is no frame or video-decoder dependency. Set `pb_set_poll_interval` to 100, 500 or 1000 microseconds (XInput only). 100 busy-waits on QPC throughout the session, including idle input (about one core); 500/1000 use a high-resolution waitable timer, requesting half the interval for 500 because Windows rounds waits up to its ~0.5 ms tick (measured: a 500 us request waited ~1 ms). These are sampling intervals, not USB polling frequency. The input thread uses below-normal priority during extreme-mode spinning; other input/feedback scheduling is high but below realtime; Takion receive priority is above normal. Guide/PS and touchpad-click can be supplied with `pb_button` because standard XInput does not expose those buttons. XInput-compatible modes on Xbox/third-party controllers are supported; other HID/DirectInput layouts need their vendor's supported XInput or DS mode. Connecting without a controller is allowed so a controller can be plugged in later; `controller_present` reports the live slot availability.

Audio and video are disabled through upstream `CHIAKI_AUDIO_VIDEO_DISABLED`. The upstream session requests its 360p/2 Mbps/maxFps=0 profile and discards media packets on receipt. No decoder, renderer, GUI library, audio playback or microphone encoder is included. This does **not** establish that the PS5 stops all media traffic; validate that with capture on the real PS5 firmware.

`pb_start` returning 0 means the session thread started. Only `PB_CONNECTED` in `pb_get_status` confirms the console completed the connection. A login-PIN request is distinct from pairing and accepts the console's four-digit login PIN through `pb_set_login_pin`. Pairing uses the raw eight-byte PSN Account-ID and the numeric eight-digit device PIN (leading zeros are permitted). Returned per-account credentials contain the registration key and morning key. The native host value accepts a hostname or IP address, without URI/port syntax.

Stop signals and joins the input thread, submits a neutral report (sent synchronously) and allows 30 ms for its repeat, then stops/joins/finalizes libchiaki. The controller-disconnect path submits neutral input. Delivery to the console cannot be guaranteed after an already broken network connection. Registration cancellation uses `pb_stop`; registration is synchronous and callers must await that call's completion before destroying its context. `pb_destroy` must not run concurrently with outstanding ABI calls.

HID defaults to no per-report QPC, floating-point timing or latency-window writes. Basic sample/submission/error counters and retry semantics remain active; timing getters return empty measurements for an untraced HID selection, including after switching from XInput. `PS5BRIDGE_TRACE=1` restores HID timing for diagnostics. The UI displays a dash for absent timings. XInput detailed timing is also disabled by default and can be enabled with `PS5BRIDGE_XINPUT_TIMING=1` or `PS5BRIDGE_TRACE=1`.

When enabled, timing statistics measure QPC time from **after** XInput returns a captured state (or the application consumes a HID report) to successful return from `chiaki_session_set_controller_state`. Normal changed-input submissions include encryption and UDP `send`; a pending submission already recovered by the background worker may return without sending again. Only successful submissions while `PB_CONNECTED` count; preconnection caching is excluded. They exclude device/USB polling, driver queues, waiting for capture or thread wakeup, network delivery, console processing and HDMI display. `input_reports` counts foreground submissions, not transmitted UDP packets.

ABI 4 adds the 72-byte `pb_latency_stats` and `pb_get_latency_stats`: submit and capture-interval counts, submit P95/P99, interval mean/P95/P99/max, and foreground submission failures. Each count describes a separate window of at most 1024 samples, reset on `pb_start`; percentiles use the nearest rank. Intervals require a connected session and consecutive present samples from the same controller index; handshake, unplug and device switching do not create long artificial intervals. The sampling thread only appends to fixed arrays; snapshot reads copy under the lock and sort after releasing it. Submit failures are failed foreground setter calls, including repeat calls while an error is pending, not UDP packet losses; background retries are not counted. These metrics must not be presented as PS5 end-to-end latency or compared directly to a hardware-adapter latency number.

Verification: `tests/test_abi.py` loads the actual DLL and validates struct sizes, empty-key rejection, native stick/button/neutral conversion, the HID device list against the controller mask, DS4/DualSense report parsing (via `pb_self_test`), 20 create/stop/destroy cycles, cancellation of a real registration worker, and stop/join while an actual loopback TCP peer withholds the console response. Those tests require no account secrets or PS5. They do not verify PS5 hardware connectivity, controller USB timing, firmware behavior, complete media suppression, or end-to-end latency. The initial test run failed because the implementation DLL was absent; the compiled implementation makes the contract tests pass.

The upstream library is AGPL-3.0 with its OpenSSL exception text. Preserve the source/build instructions and licenses when distributing this binary. Protocol and optional diagnostics edits are checked changes in `patches/chiaki-edits.json`; retained crypto optimizations are in `patches/chiaki-low-latency.json` (feedback sender: send on the caller's thread; `session.c`/`takion.c`: return send errors). There are no whole-file replacements. `scripts/bootstrap.py` applies them, rejects an unexpected upstream baseline, re-extracts sources whenever a pin changes, and lists dependency URLs and pins.

The native build runs sender fault injection, input-worker regressions, a real encryption/Winsock loopback error-recovery test and Python ABI/lifecycle/bootstrap tests. See `../docs/validation/2026-10-23-latency-reliability.md`. The sender test replays packets through two receiver models (only the first event applied, as reported upstream with a zero event count; and the announced event count applied); neither is a PS5. No acknowledgement or delivery guarantee is provided.

ABI 5 extends `pb_hid_info` to 1608 bytes with a 1536-byte UTF-8 device interface path. `pb_start_device` and `pb_set_controller_device` bind that identity instead of reinterpreting an enumeration index. A generation counter rejects reports from an obsolete selection; changing selection releases old input without waiting for a report from the new HID. A missing device never falls back to another HID. A different USB port or Bluetooth connection can create a different identity and requires re-selection. Legacy index setters resolve the device once rather than following later reordering.

`pb_get_controller_status` returns an independent 8-byte device state/system error pair. Device offline, access failure and read failure do not mark the PS5 session disconnected. Managed `UpdateOptionsAsync` changes the controller and poll interval in place under the lifecycle gate; the coordinator rejects queued updates belonging to a superseded connection. The 100/500/1000 us choices and 500 us default remain available.

ABI 6 adds the 80-byte `pb_input_health` snapshot and `pb_get_input_health`. XInput diagnostics retain completed-read counts, packet changes, real read failures, raw axes/buttons/triggers, last call duration, read/packet-change ages (-1 before the first observation), and a once-per-call stall counter. Selection changes reset this device-specific evidence. Packet age is observational: unchanged packets are legal for held input. A separate watchdog checks pending XInput calls every 50 ms and submits neutral after a 250 ms deadline; a resumed read can resume control, but the bridge cannot safely terminate a hung driver call or identify stale successful driver snapshots. Shutdown can still await an unresponsive driver. History tail resends follow upstream at 20/50/100/200 ms with new sequence numbers. See `../docs/validation/2026-10-25-input-recovery.md`.

The upstream sender is notified on each changed sample to schedule its tail resends. Historical 8K benchmarks below describe the previous custom sender. Sampling helpers rely on their existing caller-held context lock rather than re-entering it for every statistic. Public ABI and synchronous first-send semantics are unchanged. `tools/latency-8k/run.py` compares a frozen pre-change build with the current build using a 125 us synthetic latest-state timeline, the real input worker and encrypted UDP loopback. See `../docs/validation/2026-10-26-8k-input-optimization.md` for measurements and limitations.
