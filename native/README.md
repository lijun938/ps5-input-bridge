# Windows native PS5 input bridge

`ps5bridge.dll` exports the versioned C ABI in `include/ps5bridge.h`. The UI owns account profiles and DPAPI storage; this DLL owns PS5 registration, a single local-network session, and an independent controller input thread. It never requests putting the console into rest mode.

Build from the repository root with:

```powershell
pwsh -NoProfile -File tools/build-native.ps1
```

The bootstrap downloads the pinned chiaki-ng v1.10.0 commit `0c4a45df0cae2af2ba2daef84e881850b07038a3`, its pinned submodules, mbedTLS 2.28.0, json-c 0.17, miniupnpc 2.2.8, libevent 2.1.12, protoc 25.3, and a SHA-256 checked LLVM-MinGW 20261006 toolchain. CMake 3.31.6, Ninja 1.11.1.4 and protobuf 4.25.6 are installed in a project-local Python environment. Python 3.11+ and Internet access are needed on the first build. Downloaded sources, tools, build files and output binaries are ignored by Git; neither a system compiler nor an administrator installer is required. Release output is `native/out/ps5bridge.dll` (x64). Its dependencies are Windows system DLLs only.

Controller indices 0–3 are Windows XInput slots; indices 4 and above are HID gamepads read directly (`pb_hid_devices` lists them in device-path order; `pb_controller_mask` sets bit 4+n for each). HID pads are recognised by a Sony vendor ID, or by the DualShock 4 / DualSense report sizes (input 64, output 32/48, feature 64) for third-party pads in DS mode; the parser handles USB report 0x01 and the Bluetooth reports 0x11 (DS4) / 0x31 (DualSense), and reads the calibration feature report once so a Bluetooth pad switches to its full report. Each input report is consumed as it arrives from an overlapped `ReadFile` (8 queued buffers), so there is no sampling interval on that path; sticks map 0x80 to 0 with the full signed range, triggers are the raw bytes, two touchpad contacts are forwarded with DS4 rows rescaled to the PS5 range, and the IMU is not forwarded. Device enumeration is cached for 1 s. The XInput path uses the original signed stick range and trigger bytes, without adding a deadzone or curve. Every sample whose state changed is submitted at once (no analog coalescing). The patched feedback sender encrypts and sends on the input thread; its worker only repeats the latest history packet verbatim (2/8/24 ms after a change) and sends the 200 ms stick keepalive. History packets carry each control once with its current value, newest first, so a trigger sweep cannot evict a button edge. The input thread joins MMCSS "Pro Audio"; `PS5BRIDGE_TRACE=1` writes an edge trace CSV to `%LOCALAPPDATA%\PS5InputBridge` on stop. Input capture does not run on the UI thread, and there is no frame or video-decoder dependency. Set `pb_set_poll_interval` to 100, 500 or 1000 microseconds (XInput only). 100 busy-waits on QPC (one core while connected); 500/1000 use a high-resolution waitable timer, requesting half the interval for 500 because Windows rounds waits up to its ~0.5 ms tick (measured: a 500 us request waited ~1 ms). These are sampling intervals, not USB polling frequency. Input/feedback thread priority is high, below realtime; Takion receive priority is above normal. Guide/PS and touchpad-click can be supplied with `pb_button` because standard XInput does not expose those buttons. XInput-compatible modes on Xbox/third-party controllers are supported; native DirectInput/HID controllers need their vendor's XInput mode or a separate compatible driver. Connecting without a controller is allowed so a controller can be plugged in later; `controller_present` reports the live slot availability.

Audio and video are disabled through upstream `CHIAKI_AUDIO_VIDEO_DISABLED`. The upstream session requests its 360p/2 Mbps/maxFps=0 profile and discards media packets on receipt. No decoder, renderer, GUI library, audio playback or microphone encoder is included. This does **not** establish that the PS5 stops all media traffic; validate that with capture on the real PS5 firmware.

`pb_start` returning 0 means the session thread started. Only `PB_CONNECTED` in `pb_get_status` confirms the console completed the connection. A login-PIN request is distinct from pairing and accepts the console's four-digit login PIN through `pb_set_login_pin`. Pairing uses the raw eight-byte PSN Account-ID and the numeric eight-digit device PIN (leading zeros are permitted). Returned per-account credentials contain the registration key and morning key. The native host value accepts a hostname or IP address, without URI/port syntax.

Stop signals and joins the input thread, submits a neutral report (sent synchronously) and allows 10 ms for its repeat, then stops/joins/finalizes libchiaki. The controller-disconnect path submits neutral input. Delivery to the console cannot be guaranteed after an already broken network connection. Registration cancellation uses `pb_stop`; registration is synchronous and callers must await that call's completion before destroying its context. `pb_destroy` must not run concurrently with outstanding ABI calls.

Timing statistics measure QPC time from **after** XInput returns a captured state to the return from `chiaki_session_set_controller_state`, which now includes encryption and the UDP `send`. They exclude device/USB polling, time waiting for the native poll timer, network delivery, console processing and HDMI display. `input_reports` counts submissions to libchiaki, not transmitted UDP packets. These metrics must not be presented as PS5 end-to-end latency or compared directly to a hardware-adapter latency number.

Verification: `tests/test_abi.py` loads the actual DLL and validates struct sizes, empty-key rejection, native stick/button/neutral conversion, the HID device list against the controller mask, DS4/DualSense report parsing (via `pb_self_test`), 20 create/stop/destroy cycles, cancellation of a real registration worker, and stop/join while an actual loopback TCP peer withholds the console response. Those tests require no account secrets or PS5. They do not verify PS5 hardware connectivity, controller USB timing, firmware behavior, complete media suppression, or end-to-end latency. The initial test run failed because the implementation DLL was absent; the compiled implementation makes the contract tests pass.

The upstream library is AGPL-3.0 with its OpenSSL exception text. Preserve the source/build instructions and licenses when distributing this binary. The upstream feedback sender is modified; the complete modified files are in `patches/chiaki/` and are copied over the pinned source by `scripts/bootstrap.py`, which also lists dependency URLs and pins.
