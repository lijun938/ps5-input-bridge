# 2026-10-29 扳机释放与反馈包事件数修复

目标版本：1.0.4，原生公共 ABI 仍为 6。

## 故障条件与定位范围

用户报告 Xbox 手柄会偶发自行开镜或持续开镜，补按几次左扳机后恢复；扳机已改装为微动。另一只 DSE（DualSense Edge）经 **USB 有线、HID 直读**也会出现持续开镜。因此本次核对两条输入路径及其共同的 Remote Play 发送链路。

XInput 的 `bLeftTrigger` 与 DSE USB 完整报告的 L2 字节均直接转发；HID 每份有效报告先初始化为空闲状态再解析，不会从上一报告继承扳机值。微动扳机仍经过这些数值字段，因此不能仅凭硬件类型判断桥接已正确释放。

既有 [XIM 卡键诊断记录](2026-10-26-xim-stuck-buttons.md) 曾记录故障仍在时 PC 原始 `L2=0`，且读取和提交均无错误。这是共同发送链路的调查线索，不是本次 DSE 故障的新现场抓包。

## 已确认的代码缺陷

固定的 chiaki-ng 基线 `0c4a45df0cae2af2ba2daef84e881850b07038a3` 在 `lib/src/takion.c` 构造 feedback history 与 feedback state 包时，把包头第 3 字节（从 0 计数）恒设为 `0`，注释为 `TODO`。该字段实际是载荷内的事件数或状态数。

本项目发送器会把多个按钮、L2、R2 和触摸事件放进一个 history 包。按钮/扳机按最近变化顺序排列，L2 和 R2 在同一采样中变化时，后处理的 R2 位于 L2 前面。例如：

1. L2 已按住，主机进入开镜。
2. 同一采样中 L2 从 255 变为 0，R2 从 0 变为 255（或由 255 松开为 0）。
3. 发出的载荷以 R2 事件开头，L2 松开在后；旧版头部事件数仍为 0。
4. 如果主机只处理最前面的事件，L2 松开会被忽略。之后补发相同内容仍遗漏 L2；单独补按并松开 L2 后，L2 排到最前，故障才可能解除。

这解释了为什么输入层已经松开、发送函数也成功，游戏仍可持续开镜。它不依赖模拟扳机漂移，也同时影响 XInput 与 DSE USB。它证明存在可导致该症状的协议缺陷，但没有现场证据证明用户每次“自行开镜”均由同一原因引起。

## 上游实机证据

[chiaki-ng PR #840](https://github.com/chiaki-ng/chiaki-ng/pull/840) 于 2026-10-09 合并，提交为 `c8bea2642d0e95402f373af55584a3b98cd89417`。作者在 macOS + PS5 + GT7 的油门/刹车显示中验证：合并 L2 与 R2 更新、事件数为 0 时只有 R2 正常；事件数填写为实际数量后两枚扳机都生效。测试特意关闭了此前逐事件拆包的绕行方案。

该补丁明确把 history 的事件数设为**整个载荷内的事件数量**，包括保留历史，并为每个缓存包及尾部补发保存对应数量；state 包的数量设为 1。它不是“本次采样刚变化的控件数”。

此前 [PR #823](https://github.com/chiaki-ng/chiaki-ng/pull/823) 也记录过真实 PS5 上同包 L2/R2 只生效一项、触摸和点击同时释放时遗漏一项的现象。[PR #838](https://github.com/chiaki-ng/chiaki-ng/pull/838) 则处理最终释放 UDP 包丢失。三者是相关但不同的问题：本次修复的是缺失事件数，不能把成功的本地发送等同于主机已应用全部事件。

## 修复范围

- History 包头填写实际载荷的总事件数，包含按钮、扳机与触摸事件；补发保持与载荷匹配的数量。
- Feedback state 包头填写 1。
- 保留已有控件快照、同步首发、2/8/24 ms 补发及 200 ms 保活。历史补发继续复用原序号；本次没有证据要求更改这一策略。
- 不新增扳机死区、去抖延迟或长按强制松开规则；正常持续开镜和快速微动操作仍直接转发。
- 应用版本提升到 1.0.4，以便区分复测结果。

传输层修改记录在 `native/patches/chiaki-return-errors.json`，由 bootstrap 对固定基线检查后应用；反馈发送器的完整替换文件仍位于 `native/patches/chiaki/`。

## 本地验证

修复前已用真实 UDP 封包复现：载荷分别含 2 个事件、22 个事件以及 1 个 state 时，包头数量均为 0，三项断言失败。修复后数量分别为 2、22、1，载荷解密一致；原有 8 组加密报文/GMAC 对照与小包分配检查通过。

## 实机边界与后续问题

本次没有连接用户的 PS5，尚未完成该 Xbox 微动手柄或 DSE USB 的真实游玩复测。上游的 PS5 实验支持协议修复，本地测试验证代码和封包；两者不能替代用户环境下持续开镜是否消失的验证。

排查还发现 DualSense 蓝牙 simple 报告的独立解析问题：`0x01` 的 10 字节或填充至 78 字节 simple 报告与 USB 64 字节完整报告的字段位置不同，现有解析未区分。用户确认使用 USB，故本次未修改此分支；该发现不能解释当前已确认的 USB 连接条件，也不能据此声称已覆盖蓝牙 simple 模式。
