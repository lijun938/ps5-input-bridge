# 2026-10-26 HID 读取路径精简

应用版本 1.0.3，公共 ABI 仍为 6。本轮聚焦 HID 延迟，保留输入映射、每个状态变化的同步发送、按键顺序、原有补发和失败重试语义。没有修改 USB、Windows 调度或网络设置，也没有引入摇杆合并或平滑。

## 最终实现

- 正常 HID 报告从约六次 context 锁进入减少到一次；发送前在该锁中检查设备身份、generation 和停止状态，同时读取界面特殊按键和更新设备状态。
- `ReadFile` 同步完成后跳过 `WaitForMultipleObjects`，异步读取仍事件驱动。由 `ReadFile` 自动复位 OVERLAPPED 事件，去掉重复 `ResetEvent` 系统调用。参照微软 [ReadFile 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-readfile) 的异步 I/O 事件语义。
- 所有生产停止信号来源（显式停止、session QUIT、看门狗创建失败）在 context 锁中先设置停止状态。因此同步完成路径也能在提交前拒绝旧输入，无需每份报告额外查询停止事件。
- 保留单缓冲、单个未完成请求。解析后、加密发送前继续提前投递下一次读取；如果续读立即失败，先处理刚完成的有效报告，再走原有中立释放路径。
- 默认 HID 不执行逐报告 QPC、浮点延迟计算和延迟窗口写入。基础报告/样本/错误计数、按键边沿计数和重试逻辑保留。`PS5BRIDGE_TRACE=1` 可恢复计时；会话计时开关独立于 CSV 缓冲，停止并释放缓冲后仍可读取统计。
- 默认 HID 的计时 getter 返回空测量，避免显示前一个 XInput 设备的旧数据；UI 正确显示破折号及提交/失败次数，不显示 NaN 或虚假的零延迟。XInput 仍默认计时。

双缓冲曾单独对照：只改变缓冲数量及解析/续读顺序，1K/8K 的平均差分别约 0.065/0.088 μs，8K 每对方向不一致，没有稳定净收益，因此最终采用更简单的单缓冲。初版每报告额外查询停止事件也未保留。完整实验记录在 `artifacts/latency-hid/initial-ab` 和 `buffer-ablation`，包含当时工具快照，未删除不利结果。

## 功能验证

新增受控 I/O 测试直接运行生产 `hid_session`，Windows 锁和事件真实执行，替换设备和 I/O 边界，不读取真实手柄。

- 初始冻结基线为 7/13，明确复现同步完成多余等待、续读失败丢当前边沿、停止期间仍提交旧输入和默认逐报告计时等问题。
- 最终 HID 16/16：同步/异步按下释放、短包恢复、续读失败先提交再释放、失败重试、停止/切换/真实 session QUIT 在完成及续读阶段阻止旧输入、取消后回收请求，以及默认无 QPC 与 trace 恢复/停止保留统计。
- 既有 input worker 30/30、feedback 13/13、wakeup 3/3、416 组加密向量、8 种真实 UDP 历史包和发送错误恢复通过。
- Python ABI/生命周期/bootstrap 12/12；托管 84/84；WPF 离线检查 87/87。
- 项目原生源码及新增测试用 `-Wall -Wextra -Werror` 构建。

证据：`artifacts/latency-hid/native-build.log`、`managed-tests.log`、`ui-checks.log`、`hid-tests/before.txt` 和 `hid-tests/after-stop-quit.txt`。

## 性能测量边界

`tools/latency-hid/run.py` 执行真实 input worker、HID 循环、session、feedback、AES/GMAC 和 UDP 环回，使用生产 local crypto index 2 及 256 KiB 后台密钥流缓存。独立线程按 1K/8K 固定时间轴生成 DS4 报告，通过真实 Windows 事件通知。报告每次改变轴、扳机并交替 L1，用于检测遗漏边沿。

适配器显式模拟深度为 8 的 FIFO，满时丢最旧排队报告；这不是对 Windows HID 驱动溢出策略的声明。积压工况约每 100 ms 注入一次 `Sleep(1)`，同时记录其实际耗时。生产线程、调度、温度和 CPU 频率未严格控制。

外部时间戳独立于被关闭的产品计时，分别记录计划生成、实际生成、I/O 完成、读取和提交。主比较使用实际生成至本地提交，避免因代码跨越内部计时点导致虚假改善。提交成功不表示 PS5 已收到。测试不涉及真实 USB、局域网或 PS5，不能证明真实 HID 回报率或端到端延迟。

最终对照数据和构建/原始 CSV 哈希位于 `artifacts/latency-hid/final-ab/`。冻结 1.0.2 的匹配源码、头文件和静态库位于 `artifacts/latency-hid/baseline`，初始哈希见 `baseline-manifest.json`。

每工况 3 对、改前/改后交替，共 18 轮；每轮预热 0.5 秒、测量 3 秒。以下分位数为三轮分位数的平均，并非池化分位数。

| 工况 | 实际生成→本地提交均值（μs，改前→改后） | P99（μs，改前→改后） |
|---|---:|---:|
| 1K 连续变化 | 30.098 → 29.724 | 38.933 → 37.000 |
| 8K 连续变化压力 | 21.116 → 20.550 | 34.733 → 34.867 |
| 8K 人为积压压力 | 28.532 → 29.231 | 298.267 → 292.333 |

稳态平均改善只有约 0.37 / 0.57 μs；不能称为毫秒级改善，8K 稳态 P99 也没有改善。1K 每版共 9,000 份、8K 稳态每版共 72,000 份测量报告均无遗漏按键边沿、无 FIFO 丢报告。全部工况前台提交失败为零。

积压测试每版 72,000 份报告，模拟 FIFO 丢报告 108→117，缺失交替按键边沿 138→150；最终改动未解决调度暂停时的积压和边沿损失，也未引入丢旧输入的策略。注入暂停的实际时长及调度不完全一致，不能据此声称丢边沿改善或退化已得到硬件验证。

工作线程 cycles/report 在稳态 1K 为 117610→115855、8K 为 80143→77641；频率与系统负载未固定，不能直接换算成整机 CPU 节省比例。当前软件模型支持小幅处理成本下降，真实 HID/USB 和 PS5 响应仍未测量。
