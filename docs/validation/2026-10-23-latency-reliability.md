# 延迟与发送可靠性优化验证

2026-10-23，Windows x64，.NET SDK 9.0.312，Python 3.11，项目固定 LLVM-MinGW 工具链。用户已批准实施延迟优化，并要求保留 100 μs 极限档；100 / 500 / 1000 μs 均保留，默认仍为 500 μs。既有 Chiaki 导入改动保留在工作区。

## 改动与证据

| 场景 | 修复前证据 | 当前行为及验证 |
| --- | --- | --- |
| 摇杆最后位置/回中包丢失 | 70 ms 内无法恢复，需要等待 200 ms 保活 | 独立 2/8/24 ms 最新状态补发；本轮故障注入回中约 2.6 ms 恢复 |
| 本地 UDP 发送错误 | Takion、sender、session 吞掉错误；真实无效 socket 返回链测试显示三个错误判定均为 0 | 完整返回错误，保留待发状态；真实加密/GMAC/Winsock 测试三个错误判定均为 1，换为 loopback socket 后无需新输入即可恢复 state/history |
| 超过 8 个控件同时释放 | 旧测试同时按下/释放会漏掉同一批控件；改成依次按住 18 个再释放可复现遗留按下 | 历史包保留完整控件；确认先收齐 18 个按下，再全部释放 |
| 发送失败后输入回到原基线 | 输入线程过滤最终 idle，sender 继续重试旧按下/摇杆位置 | pending 标志确保最终值仍提交；回归先失败、修复后通过 |
| 切换手柄时发送连续失败 | 复核新增测试失败：重复 neutral → 新状态，绕过错误重试间隔 | 已观察到的槽位与最后成功状态分别维护；一次切换仅注入一次 neutral，之后仅重试最新输入 |
| 本地失败的触摸释放随后遇到按键变化 | 失败的 touch-up 被下一包清掉 | 以最后成功历史状态构造触点事件；回归通过 |
| 延迟统计受握手缓存干扰 | 未连接时成功缓存也计入提交 | 仅连接后的成功提交计时；Python 和托管 loopback 握手测试确认计数为 0 |

最初扩充的 8 项 sender 回归在旧实现上只有 3 项通过，修复后全部通过。随后补充局部 state/history 失败、重试次数有界、重复相同输入不持续发包及关闭时最后 neutral 补发，总计 11 项通过。网络故障持续 45 ms、超过三次短补发后，仍能通过后台约 8 ms 重试恢复。新状态能覆盖旧状态，含 16 位序号回绕。

`session.c` 与 `takion.c` 使用固定源码的精确替换补丁；重复应用和不匹配拒绝测试通过。两处完整 sender 文件与 JSON 补丁均随源码包分发。

## 统计与界面

- ABI 升级到 4，新增 72 字节 `pb_latency_stats`，原生静态断言、Python 与 C# 布局检查一致。
- 成功提交耗时与采集间隔分别保留最近最多 1024 个样本；采样线程只写固定数组，快照读取复制后在锁外排序。最近秩 P95/P99 测试验证旧极值会过期。
- 采集间隔排除握手、设备缺失、槽位切换边界；HID 反映读取报告间隔，XInput 反映采样间隔。
- 失败数是本次连接的前台 setter 失败调用数，包含错误等待期间重复调用，不是 UDP 丢包数；后台重试失败不直接计入。
- 无样本时显示破折号。正常和最小窗口宽度下，长统计文本能换行，滚动后内容完整；100 μs 可选，500 μs 为默认。
- 离线截图使用合成数据：`artifacts/chiaki-ui-validation/latency-620.png`、`latency-760.png`。未展示真实账户或现场延迟。

## 本机采样测量

使用真实 Windows 输入工作线程和等待策略，替换 XInput 状态来源及提交边界。每档采集 4000 次；下表分位数取末尾 1024 个间隔。该测试包含新增统计记录开销，不含真实 USB、加密发送、网络或 PS5。

| 档位/状态 | 全程平均间隔 | 近期 P95 | 近期 P99 |
| --- | ---: | ---: | ---: |
| 100 μs，持续变化 | 100.2 μs | 100.3 μs | 100.8 μs |
| 500 μs，持续变化 | 501.7 μs | 514.0 μs | 518.2 μs |
| 1000 μs，持续变化 | 1199.6 μs | 1548.5 μs | 1658.4 μs |
| 100 μs，保持不动 | 1193.3 μs | 1719.8 μs | 2003.9 μs |

100 μs 活跃时约占用一个 CPU 核心，空闲后回到低耗等待。CPU 时间分辨率较粗，短测输出的 0%/101% 不应解读为严格占用率。系统负载会影响数值；这些结果说明档位行为保留，不是 PS5 端到端延迟提升倍数。

## 实机边界

未连接真实 PS5、未读取真实账户文件、未改 Windows 网络或电源设置。模拟回中包丢失后的约 2.6 ms 是发送器/接收模型恢复时间，真实固件响应和屏幕延迟仍需实测。

完整 18 控件历史目前最大 48 字节，加最多四个触点事件共 68 字节，小于 0x300 缓冲区；上游历史长度也并非 8 事件协议字段。但全部 PS5 固件是否接受此载荷，尚无实机证据。持续断网时，停止/关闭的最后释放只能尽力发送，无法保证送达。

触摸释放本轮覆盖的是本地发送失败：若 UDP 返回成功而包在网络中丢失，随后新按键/触摸变化重建历史包，旧 touch-up 仍可能被替换。没有增加主机确认机制，不能宣称消除全部 UDP 丢包导致的卡键。

全面评审中的多实例账户覆盖、HID 身份稳定性、依赖缓存与系统调优脚本问题未纳入本轮延迟优化，详见之前的全面评审报告。
