# 2026-10-25 转圈与输入冻结排查

## 现场证据及判断边界

用户提供的五份诊断均为 XInput、100 μs 档、应用 1.0.0.0。去重后有 13 次手柄离线再恢复，每次约 2–5.5 秒，期间 PS5 会话保持连接；最后一段在北京时间 20:18–20:24 内出现 5 次。用户确认故障时界面仍显示在线，需要插拔直连电脑的 USB；重开桥接程序后仍会复发。

旧日志只在状态变化时记录，缺少原始摇杆、包号及读取进度；离线事件可能就是手动插拔，不能当作最初原因。SubmitFailures=0 仅表示本地提交成功，不证明 UDP 已送达主机。旧 XInput 路径还将所有错误码写成零。

本机排查时四个 XInput 槽位均报告未连接，无法复现真实设备故障。以下为已复现并修复的软件缺口，不能据此认定所有现场故障均已解决。

## 修复

- 按键/扳机历史在 2/8/24 ms 补发后仍独立每约 200 ms 重发。100 ms 的连续丢包不再让最终释放永久丢失；持续摇杆变化不推迟历史保活。重复使用原序号和载荷。
- XInput 返回真实错误时立即释放输入，并保留错误码。设备未连接与其他读取失败分别显示，随后继续尝试读取。
- 独立监控每 50 ms 检查未完成的 XInput 调用，超过 250 ms 后先发送 neutral。正常长按、静止摇杆、相同包号不会被归零。恢复后的新读取可继续转发；选择变化与停止时释放旧输入，停止后迟到的数据不再按下。
- 读取期限超时次数按每次卡住的调用累计，恢复后仍能在诊断里看到；切换手柄会重置该设备的读取统计。
- 手柄列表采用单次后台刷新，慢驱动探测不会阻塞界面或堆积刷新任务。
- 应用版本 1.0.1、原生 ABI 6、诊断格式 2。增加最多 256 条每秒读取记录：原始按键/摇杆、包号、真实错误、读取/包变化年龄和调用耗时。无账户、地址、设备路径或密钥。包号不变本身不是故障。

## 实机限制和复测

未连接真实 PS5 或故障手柄。接收端模型验证不能代替 PS5 固件验证。监控只能释放卡住读取留下的按键，不能安全强杀 Windows 驱动调用；若驱动永远不返回，关闭仍可能等待它。驱动若持续成功返回旧值，与真正长按无法可靠区分，因此没有用“包号几秒不变”强制归零。HID 无报告超时另有待处理缺口，本次现场为 XInput，未改动 HID 行为。

使用新版后若仍复发，尽量在插拔 USB 前导出诊断，并记下发生时间；可以在相同条件下对照 500 μs 档。LastReadAge 持续增加且 ReadCount 不动指向采集停滞；持续有成功读取但原始摇杆不回中，需继续排查手柄/接收器/驱动或输入源；原始摇杆已回中而 PS5 仍转动，需进一步定位发送/网络/主机链路。任何单个数值都不能证明硬件损坏。
