# 1.1.1 整合版使用

本版将 1.0.5-latency.1 的输入、统计快照和可选诊断优化合入当前版本，同时引入 1.1.0 中固定 chiaki-ng main 的 #823/#838/#840 修复。输入线程同步首发；每个变化事件单独发包并标明事件数，历史尾包按约 20/50/100/200 ms 重发。摇杆丢包由约 200 ms 保活恢复。完整程序位于 `dist/PS5InputBridge`。

完整解压发行包后：

- `launch-normal.cmd`：日常使用。XInput 和 HID 均默认关闭详细延迟统计，界面耗时显示“—”，输入次数和失败计数仍可查看。此启动方式仅清除子进程的诊断环境变量，不修改系统设置。
- `launch-timing.cmd`：只开启 XInput 详细计时，适合与普通启动对照；没有锁等待 CSV。HID 仍按报告到达处理。
- `launch-diagnostics.cmd`：排查用。开启锁等待诊断和 XInput 详细统计；连接、正常操作后点击断开，CSV 写入 `%LOCALAPPDATA%\PS5InputBridge\diagnostics`。诊断本身会增加计时开销，勿把它当成日常最低开销模式。

不同启动方式前先关闭已有程序，否则单实例保护会保留旧进程的设置。三个启动器均不自动连接主机。

## 诊断内容

`input-*.csv` 记录输入线程获取共享锁的等待，以及 HID 读取完成后的成功提交路径耗时。`feedback-*.csv` 记录前台反馈锁等待、摇杆/按键发送调用耗时和后台补发持锁时间。HID 的起点在应用取出报告后，不能当成 USB 报告到达或操作系统唤醒时刻。`xinput_select_wait` 也包括切换到 HID 之前的输入循环选择检查。

每阶段保留最近 4096 个样本，以及全程次数、累计耗时和最大值。CSV 不含按键值、设备路径、主机地址、配对资料或账号。只有断开/正常退出后导出；直接终止进程可能丢失内存记录。输出失败不会影响输入发送。已有 `PS5BRIDGE_TRACE=1` 是另一种包含按键边沿的诊断，三个启动器均不启用它。

详细时序统计以约 100ms 的间隔发布给独立快照。UI 占用快照时，输入线程跳过统计发布；显示可能暂时滞后，但不会为该快照等待。其它少量状态 getter 仍有短临界区，本版不宣称彻底消除所有共享锁。

## 实机对照

先用同一手柄、USB 接法、XInput 100μs 或同一 HID 模式、相同游戏/帧率/电视设置，使用本版普通启动。分别观察偶发迟滞、快速按下松开、L2 松开同时 R2 变化、单次换弹和摇杆回中；Xbox/XInput 与 DS/HID 模式各测一遍。切换手柄与断开也应正常释放。对照旧版时，发送器协议与重发策略也有变化，不能把手感差异全部归因于统计优化。

需要定位偶发异常时再使用诊断启动，断开后保留对应 CSV。受控 PC 环回基准不等于真实 USB、网卡或 PS5 响应测试；本版没有测得真实按键到画面的改善值。
