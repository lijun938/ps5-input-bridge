# 延迟与可靠性优化

用户已批准实施上一轮建议，并明确保留 100 μs 档。默认继续使用 500 μs；不改变 HID 事件驱动采集或 Windows 系统设置。

## 验收行为

- 当摇杆最终位置/回中包丢失，使用独立的 2/8/24 ms 最新状态补发，不等待 200 ms 保活；新输入立即发出并替代旧补发。
- 当本地 UDP send 失败，错误从 Takion、sender、session 一直返回输入线程；同一输入可重试，持续错误使用有等待的后台重试，恢复不依赖用户再次操作。
- 当一次提交失败后实际输入回到原基线，仍通知 sender，以取消过时的待发状态。
- 当切换手柄后发送持续失败，仅为该次切换提交一次 neutral，后续重试保留新手柄状态，避免重复释放/按下。
- 当多个按键同时释放，全部变化都进入历史包；触点释放在本地失败后不会被下一次按键变化抹掉。
- 界面增加本机提交及采样间隔 P95/P99、提交失败数。采样线程只写有界数据，排序在读取快照时完成；指标不声称测量 PS5/电视延迟。
- 原生测试进入构建脚本，ABI/托管/UI 验证通过。保留 100/500/1000 μs 三档并测量性能回归。

## 实现顺序

1. 扩充真实反馈发送器故障注入测试和输入线程回归，先观察旧实现失败。
2. 修复 sender 的待发送状态、错误返回与两类独立重发；对固定上游 session/takion 进行可重复、精确匹配的补丁。
3. 运行真实加密及 loopback UDP 集成测试，覆盖完整返回链。
4. 增加低开销的有界延迟样本及 UI 展示，更新 ABI 测试和文档。
5. 完整构建/回归/代码审阅，生成本地可运行版本及验证记录。实机协议兼容性和端到端延迟仍需用户 PS5 验证。
