# PS5 Input Bridge Implementation Plan

**Goal:** 在 Windows 上交付可运行的 PS5 Pro 局域网手柄桥接原型，以降低 PC 输入等待和便捷切换已配对账户为目标。

**Architecture:** 原生 libchiaki 处理 PS5 注册、会话和独立反馈发送，原生输入线程直接读取手柄并提交状态，不经过 WPF 消息循环。WPF 只管理账户、连接与低频统计。保存的配对凭据使用 Windows DPAPI 当前用户加密。

**Tech Stack:** C / libchiaki（chiaki-ng v1.10.0 固定提交）、Windows XInput、.NET 9 / WPF、Windows DPAPI。

用户于 2026-10-09 明确指示“先开发吧”，并确认目标为最低延迟和便捷切换账户。本计划据此直接执行，不增加设计审批步骤。当前仓库没有既有应用或提交，在 `codex/ps5-input-bridge` 分支开发。

## 行为与验收

- WHEN 添加账户并输入有效 Account-ID / 配对码，THEN 原生库执行注册，成功后保存加密配对凭据；失败时显示可处理错误，不留下虚假的已配对账户。
- WHEN 选择已配对账户并连接，THEN 使用其主机和凭据建立局域网 Remote Play 输入会话，关闭普通音视频处理，界面显示真实连接状态。
- WHEN 连接中切换账户，THEN 先释放输入并停止旧会话，确认资源关闭后连接新账户；同一时刻仅有一个活动会话。
- WHEN 手柄断开或主动停止，THEN 发送中立状态并清理输入线程；异常不能造成 UI 卡死或旧账户仍被控制。
- WHEN 未配对、无有效手柄或主机不可达，THEN 明确报错并允许重试。
- PC 采集与提交发送之间的耗时仅作为客户端指标，不能标为完整输入延迟。与 FGC 2 的比较仍需要实机 A/B。

## Task 1: 原生协议与输入后端

**Files:** `native/`、`tools/build-native.ps1`、固定版本依赖下载与许可记录。

1. 检查稳定版 libchiaki 最小 CMake 配置，固定源码与依赖版本，不引入 GUI、视频解码或音频播放。
2. 定义并冻结简单 C ABI：注册、会话启动/停止、状态与采集统计、控制器枚举。
3. 在实现前编写有意义的 ABI / 输入转换 / 参数校验测试，确认失败，再实现通过。
4. 原生输入独立线程使用高精度等待，不在热路径分配对象、同步写日志或等待 GUI。保留反馈发送器的可靠按键历史。
5. 编译 x64 DLL，验证加载、导出、控制器断开、无主机时失败与停止路径。

## Task 2: 账户存储与会话协调

**Files:** `src/Ps5Bridge.Core/`、`tests/Ps5Bridge.Tests/`。

1. 为账户保存/读取、加密、异常文件、会话切换和失败恢复先写失败测试。
2. 实现明确的账户模型、原子保存和 DPAPI 密文；不保存 PSN 密码。
3. 实现串行会话协调器，切换时 stop-before-start，支持取消和真实后端状态更新。
4. 测试并发请求、停止失败、连接失败、账户切换，不让不同账户共享配对密钥。

## Task 3: Windows 界面与原生互操作

**Files:** `src/Ps5Bridge.App/`。

1. 账户列表、添加/配对、主机 IP、手柄选择、连接/断开；连接时选择另一账户直接切换。
2. 清楚显示等待、已连接、失败和手柄断开；切换不要求重复 PSN 登录。
3. 使用原生 ABI 实现后端，处理异常、回调/句柄生命周期；低频读取统计，不参与输入采集。
4. 构建并启动验证；准备明确的首次配对说明和快捷启动入口。

## Task 4: 验证与交付

**Files:** `README.md`、`tools/publish.ps1`、`dist/`。

1. 集成原生 DLL，运行构建、格式/静态检查及必要测试。
2. 独立评审账户隔离、停止顺序、资源寿命和输入线程等待。
3. 发布 Windows x64 可执行包，加入源码/第三方许可说明。
4. 验证启动和本地无主机失败路径，记录已测与未测范围。
5. 实机注册、PS5 Pro 输入、完全停传媒体和 FGC 2 延迟对比需要主机/IP/配对码；不将本地测试写成实机成功。
