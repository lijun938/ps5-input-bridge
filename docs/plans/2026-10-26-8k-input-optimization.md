# 8K XInput 发送路径优化

用户已确认实施上一轮源码审查提出的优化。本轮保留 100/500/1000 μs 档位、公共 ABI、输入映射、首次同步发送、按键释放、失败重试与 2/8/24 ms 补发和 200 ms 保活语义。

1. 保存改前源码、Chiaki 头文件和静态库，供独立 A/B；位置为 `artifacts/latency-8k/baseline`，记录 SHA-256。
2. 补发线程只在新的工作截止时间早于实际等待截止时间时唤醒；先验证连续变化不再逐包通知，同时新输入、错误恢复和停止仍及时处理。
3. 小输入包使用有界缓冲；消除重复 GCM starts，复用 GMAC 密钥上下文；与原算法比较密文和认证码，覆盖密钥轮换、乱序旧密钥及大包回退。补丁必须能由固定上游源码重复构建。
4. 对采样线程只做可证明安全的重复锁减负，不改变共享状态的同步边界；更大范围的锁拆分需测出竞争后再决定。
5. 建立按独立 125 μs 时间轴更新的模拟 XInput 基准，真实执行采样线程、加密和 UDP 环回发送。交替运行改前/改后，报告生成至读取/提交、采样间隔、跳过时隙、失败和 CPU。该测试不代表真实 USB、局域网或 PS5 响应。
6. 执行原生回归、加密/唤醒专项、Python ABI/补丁测试及托管/UI 检查；独立审查并修复问题，更新文档和本地发行包。确认分发 DLL 与已测构建一致。

不增加 50 μs 档，不改变 Windows 系统设置，不将发送移入异步队列。持续自旋的 CPU 成本仍约为一个核心；性能收益以测量结果为准。
